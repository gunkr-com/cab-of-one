# 에이전트 ID와 자격 증명

[English](identity.md) | **한국어**

> 초안. 이 버전의 하네스는 검증 실행기가 시뮬레이션 테넌트만 지원하기 때문에 실제 테넌트에 대한 쓰기를 거부합니다. 이 안내서는 실제 환경을 미리 안전하게 준비하고, 실제 테넌트 읽기를 실행하기 위한 것입니다. 이 문서는 [identity.md](identity.md)의 한국어판입니다.

## 원칙

훅과 거부 규칙은 에이전트의 실수를 막기 위한 것입니다. 보안 경계가 아닙니다(소스 체크아웃의 `docs/threat-model.md`, 한국어판 `docs/threat-model.ko.md` 참조). 에이전트를 실제로 제한하는 것은 에이전트가 로그인하는 ID입니다. 그 ID가 읽기만 할 수 있다면, 실수나 우회가 있어도 테넌트를 바꿀 수 없습니다.

권장 구성:

| ID | 사용자 | 권한 |
|---|---|---|
| 에이전트 ID | Claude Code와 그 서브에이전트 | 읽기 전용 역할과 범위(scope)만 |
| 쓰기 ID | 변경 시점의 사람 | 변경에 필요한 가장 작은 관리 역할. 플랫폼이 지원하면 필요한 시점에만(just in time) 활성화 |
| 비상(break-glass) 계정 | 비상시의 사람 | 에이전트에게 절대 제공하지 않음. 이 계정에 닿는 변경은 `critical`로 취급 |

에이전트가 여러분 자신의 관리자 계정으로 로그인하게 두지 마십시오. 설정 인터뷰의 ID 질문에 "my admin account"(내 관리자 계정) 또는 "not sure"(모름)로 답하면, 프로필은 더 엄격한 "admin" 값으로 기록합니다. 이 값에는 두 가지 효과가 있습니다.

- 렌더링 미리보기에 알림이 표시됩니다.
- 생성된 하네스가 모든 Claude Code 세션 시작 시 경고를 추가합니다. 에이전트 ID가 admin이며 읽기 전용 자격 증명이 바람직하다는 내용입니다.

이 경고의 근거인 설정 메타데이터가 없거나 손상되었으면, 세션 시작 메시지는 대신 ID가 UNMEASURED라고 말합니다. ID가 읽기 전용이라고 가정하는 일은 결코 없습니다.

이 경고는 참고용일 뿐입니다. 에이전트의 로그인을 막지 않으며, 하네스는 에이전트가 어떤 ID나 자격 증명을 쓰는지 강제하지 않습니다. 경고는 생성된 하네스 테스트에서 다루어집니다. 실제 세션에서 Claude Code가 이를 어떻게 표시하는지는 측정되지 않았습니다.

## 쓰기 자격 증명을 에이전트에게서 멀리 두기

- **쓰기 자격 증명을 프로젝트에 저장하지 마십시오.** 인증서, `.pfx`나 `.pem` 파일, `.env` 파일, 클라이언트 시크릿이 여기에 포함됩니다.
- **자격 증명 경로의 읽기를 거부하십시오.** 자격 증명이 가까이 있어야 한다면 그 경로를 프로필의 `identity.deny_read_paths`에 나열하십시오. 생성기가 각 경로에 대해 `Read(...)` 거부 규칙을 추가합니다. 경로는 프로젝트 기준 상대 경로여야 하며 `./`로 시작해야 합니다. 예: `./secrets/**`.
- **셸 읽기도 막으십시오.** 거부 규칙은 Claude Code의 `Read` 도구에 적용되며, 셸 명령에는 적용되지 않습니다. `Bash`가 같은 파일을 읽지 못하게 하려면, 그 경로를 여러분의 사용자 설정에 있는 Claude Code 샌드박스 읽기 거부 설정에도 추가하십시오. 생성기는 사용자, 로컬, 관리형 설정을 결코 쓰지 않습니다.
- **발견된 자격 증명을 주시하십시오.** 설정 탐색은 발견한 자격 증명처럼 보이는 파일 경로를 거부 규칙 후보로 나열합니다. 그 파일을 열지는 않습니다.

승인 뒤에만 쓰기 자격 증명을 주입하는 관문 래퍼는 계획되어 있을 뿐, 만들어지지 않았습니다. 그것이 생기기 전까지는 사람이 에이전트 세션 밖에서 쓰기 ID로 실제 테넌트 쓰기를 실행합니다.

## 읽기를 위한 로그인

가드는 Microsoft Graph PowerShell을 동사로 분류합니다.

- `Get-`, `Find-`, `Test-`는 읽기입니다.
- 그 밖의 모든 동사는 쓰기입니다. `Connect-MgGraph`, `Connect-ExchangeOnline`, `Connect-AzAccount`도 포함됩니다.

결과:

- **로그인은 쓰기입니다.** 한 번의 셸 호출에서 연결한 뒤 읽는 명령은 쓰기입니다. 서브에이전트는 이를 실행할 수 없고, 메인 세션은 이를 실행하려면 열린 변경이 필요합니다.
- **새 프로세스, 새 로그인.** 각 `Bash` 호출은 새 프로세스를 시작하므로 PowerShell 세션이 호출 사이에 이어지지 않습니다. 예를 들어 읽기 전용 ID의 캐시된 토큰처럼 읽기 전용 로그인이 이미 프로세스에서 사용 가능하지 않다면, 실제 테넌트 프로브는 UNMEASURED가 됩니다.
- **Azure CLI.** `list`, `show`, `get-*` 하위 명령은 읽기입니다. `az login`은 쓰기입니다.

답할 수 없는 질문은 사람이 실행할 수 있는 정확한 명령과 함께 UNMEASURED로 기록하십시오. PASS로 기록하지 마십시오.

## 점검

- 설정을 바꾼 뒤에는 `cab doctor`를 실행하십시오. 빠진 거부 규칙과 훅, 그리고 읽지 못한 설정 출처를 보고합니다.
- 프로젝트 밖에서 이루어진 관리 쓰기와 훅이 실행되지 않은 세션을 찾기 위해 `cab audit`을 정기적으로 실행하십시오.
- 테넌트에서 에이전트 ID의 로그인 로그를 검토하십시오. 하네스는 이를 읽지 않습니다.
